# subjective-scoring v0.1.4 三版本同卷验证设计

## 目标

将当前待提交的 v0.1.3 升级结果继续推进到 `subjective-scoring v0.1.4`。验证 annotated tag 解引用提交为 `c559c1ca720d8f1c1f48ce716707af57c2b65d52`，使用完全相同的试卷和答案重新评分，并生成 v0.1.2、v0.1.3、v0.1.4 三版本对比报告。

## 固定验证输入

以下输入在三个版本之间保持不变：

- 文本、SQL、代码三套专项卷
- 每套试卷 5 道题
- `complete`、`partial`、`wrong` 三档答案
- 远程 reranker URL 与模型
- 隔离数据库、提交和轮询流程

正式试卷和生产数据库不得被验证过程修改。

## 版本数据源

- v0.1.2：`reports/scoring-validation-20260712-210421.json`
- v0.1.3：`reports/scoring-validation-20260713-070002.json`
- v0.1.4：本轮重新运行生成的最新 JSON 报告

项目最终依赖声明、锁文件和安装环境统一固定到 v0.1.4。

## 三版本报告

新增的对比工具读取三份 JSON，不重新评分。Markdown 报告至少包含：

1. 每个版本的工作流成功率、评分错误数、band hit rate、MAE 和排序准确率。
2. 三套专项卷各档总分的 v0.1.2、v0.1.3、v0.1.4 横向表格。
3. v0.1.2→v0.1.3、v0.1.3→v0.1.4 和 v0.1.2→v0.1.4 的分数变化。
4. 各版本是否满足 `complete > partial > wrong`。
5. v0.1.4 相对 v0.1.3 变化最大的题目。
6. 对文本错误答案压分、完整答案误伤、SQL 与代码稳定性的简要结论。

## 成功标准

- v0.1.4 tag 解引用提交准确。
- 16/16 固定提交完成且评分错误为 0。
- 生产数据快照保持不变。
- 完整测试套件通过。
- 三版本报告使用同一组 paper、quality、question key；缺失数据必须明确报错，不静默忽略。

## 范围限制

本轮不改试卷、不改答案、不调整评分参数，也不修正评分算法。报告中发现的问题作为后续校准依据。
