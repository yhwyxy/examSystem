# subjective-scoring v0.1.2 与专项试卷设计

## 目标

将 `examSystem` 使用的 `subjective-scoring` 依赖从 GitHub tag `v0.1.1` 更新到 `v0.1.2`，并新增文本、SQL、代码三套可直接在现有试卷系统中打开和作答的专项试卷，用于观察新版评分效果。

## 依赖更新

以下位置统一固定到 `v0.1.2`：

- `pyproject.toml` 的 uv Git source
- `requirements.txt` 的 Git URL
- `uv.lock` 的解析结果
- README 中的安装示例和版本说明
- 依赖边界测试中的预期版本

依赖仍使用公开 GitHub tag，不引入本地路径或兼容转发包。更新后通过 `uv lock` 和 `uv sync` 确认锁文件与环境一致。

## 专项试卷

在 `data/papers/` 新增三份 JSON 试卷，并在 `data/papers/index.json` 注册。每卷包含 5 道主观题，每题 20 分，总分 100 分，及格线 60 分。

### 文本评分专项卷

覆盖评分点命中、同义改写、否定冲突、数字与关键事实、分步骤说明。每题提供明确的参考答案和可拆分的 `scoring_rubric`，用于观察文本重排评分器对完整、部分正确和错误答案的区分能力。

### SQL 评分专项卷

覆盖筛选排序、分组聚合、多表连接、子查询、窗口函数。参考答案使用可解析 SQL，并明确表结构与业务要求，使 SQL 结构评分器能够比较关键语法结构，而不是依赖自然语言猜测。

### 代码评分专项卷

覆盖基础函数、输入边界、集合处理、异常处理和一个中等复杂度算法题。题目明确语言为 Python，参考答案提供可执行实现，评分规则同时关注结果、关键逻辑和边界处理。

## 数据与运行路径

试卷文件遵循现有 `paper_store` 格式：顶层包含 `paper_id`、`name`、`exam_info` 和 `questions`。题目使用现有 `short_answer` 类型，并通过评分元数据选择文本、SQL 或代码评分模式。新增试卷默认设为 `closed`，避免生成后自动对外开放；管理员可在现有页面中检查后开启。

## 验证

验证分为四层：

1. 依赖边界测试确认所有声明固定到 `v0.1.2`。
2. 试卷加载与校验确认三个 JSON 文件结构合法、题号唯一、总分正确。
3. 项目自动化测试确认依赖升级未破坏现有评分适配层。
4. 对每套试卷准备完整、部分正确和明显错误的代表性答案，运行现有评分验证流程，生成 JSON 与 Markdown 报告，记录得分、评分轨道、置信度和人工复核状态。

若远程文本重排服务不可用，报告应明确记录错误或降级状态；SQL 与代码本地评分仍继续验证，不伪造成功结果。

## 范围限制

本次不修改评分算法、不新增题型、不自动开放试卷，也不重构现有试卷管理界面。发现的评分偏差记录在报告中，后续再决定是否调整 `subjective-scoring`。
