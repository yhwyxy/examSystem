# Word 试卷转系统 JSON 设计

## 目标

将 `docs/测试用试卷--含答案/` 中的全部 Word 试卷转换为系统 `backend.question_loader.validate_questions()` 可接受的 JSON 文件，并保存到原目录下的 `json/` 子目录。

## 输入与输出

- 输入：目录中的 16 份 `.docx` 和 2 份旧版 `.doc` 试卷。
- 输出：每份试卷对应一个同名 `.json` 文件，例如 `试卷（软件开发）.docx` 输出为 `json/试卷（软件开发）.json`。
- 辅助输出：`json/conversion-report.json`，记录每份试卷的来源、题型数量、题目总数、总分、验证结果和无法自动确定的内容。
- 只有通过系统校验的试卷才标记为 `valid`；无法可靠提取答案或分值的试卷标记为 `needs_review`，不得伪造答案。

## 转换流程

1. 对 `.docx` 文件直接使用 `officecli view <file> text` 提取段落文本。
2. 对 `.doc` 文件使用 macOS `textutil` 转换为临时 `.docx`，再由 officecli 提取；临时文件不写入源目录。
3. 规范化空白、全角标点、序号和括号，但保留题干、代码、化学式与专业符号的原始含义。
4. 按“一、判断题”“二、单项选择题”“多项选择题”“简答题”等章节标题划分题型和章节。
5. 从章节标题提取每题分值；若题目自身带有“（10分）”，题目分值优先于章节默认分值。
6. 从题干括号、卷首答案表、卷末答案表以及“答：”“答案：”“解：”段落中提取标准答案。
7. 生成系统 JSON，重新计算 `exam_info.total_score`。
8. 调用 `backend.question_loader.validate_questions()` 对每份结果进行校验，并将结果写入转换报告。

## JSON 映射

每份文件采用以下顶层结构：

```json
{
  "paper_id": "software-development",
  "name": "软件开发",
  "exam_info": {
    "title": "大学生入职笔试卷（软件开发）",
    "description": "由原 Word 试卷转换生成。",
    "total_score": 100,
    "passing_score": 60
  },
  "questions": []
}
```

题型映射：

- 判断题：`true_false`，答案为 JSON 布尔值。
- 单项选择题：`single_choice`，答案为选项键字符串。
- 多项选择题：`multiple_choice`，答案为选项键字符串数组。
- 简答题：`short_answer`，答案为参考答案字符串，`scoring_mode` 为 `text`。
- 论述、计算或综合题：`essay`，答案为参考答案字符串，`scoring_mode` 为 `text`。

选择题选项统一为：

```json
{
  "options": [
    {"key": "A", "text": "选项内容"},
    {"key": "B", "text": "选项内容"}
  ]
}
```

题目 ID 在单份试卷内按顺序生成 `q1`、`q2`、`q3`，确保唯一且稳定。

## 解析策略

解析器采用确定性规则，不调用外部大模型：

- 章节标题识别允许中文数字、阿拉伯数字、空格和常见标点差异。
- 题号识别支持 `1.`、`1、`、`1．` 等形式。
- 选项识别支持 `A.`、`A、`、`A．`，以及同一段内连续排列的多个选项。
- 答案识别忽略括号内空白与分隔符，将 `A、C`、`AC` 统一为 `A`、`C`。
- `√`、`正确`、`对` 映射为 `true`；`×`、`错误`、`错` 映射为 `false`。
- 简答题答案可跨多个后续段落，直到下一题或下一章节开始。
- 任何无法唯一确定的答案、题型或分值都写入报告，不以猜测结果替代原文。

## 实现边界

- 新增独立转换脚本，不修改现有出题、判分或管理端行为。
- 输出文件只写入 `docs/测试用试卷--含答案/json/`。
- 不修改原始 Word 文件。
- 不自动写入 `data/papers/`，也不更新系统试卷索引。
- 临时 `.docx` 与中间文本存放在系统临时目录，转换结束后不作为交付物保留。

## 错误处理

- officecli 或 `textutil` 执行失败：该文件记为 `extraction_failed`。
- 未识别到题目：该文件记为 `parse_failed`。
- 题目缺少标准答案或有效分值：该文件记为 `needs_review`。
- 系统结构校验失败：记录完整错误消息并记为 `invalid`。
- 单份文件失败不阻止其余文件继续转换。

## 测试与验收

解析器先以测试驱动方式覆盖以下行为：

1. 判断题的真假符号转换。
2. 单选题和多选题的选项、答案拆分。
3. 同段多个选项与跨段选项解析。
4. 卷首集中答案表解析。
5. 简答题跨段参考答案合并。
6. 章节默认分值和题目显式分值优先级。
7. 缺失答案时进入 `needs_review`，而不是生成伪答案。

最终验收条件：

- 18 份源文件均出现在转换报告中。
- 每个标记为 `valid` 的 JSON 均能通过 `validate_questions()`。
- 所有 JSON 均为 UTF-8、可被 Python `json` 模块读取。
- 题目分数之和与 `exam_info.total_score` 完全一致。
- 输出目录不包含临时 Word 文件或中间文本。
